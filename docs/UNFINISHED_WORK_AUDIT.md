## Part IV — Current verification boundary

The sandbox can verify deterministic code behavior, formatting, TypeScript, Prisma generation/validation, unit/contract tests, guide completeness, OSS completeness, production build, local FFmpeg behavior, and browser E2E behavior against a local or preview server. It cannot prove provider success, GPU throughput, social publication, payment settlement, cloud failover, legal approval, or production SLOs without the external resources listed above.

The correct completion rule is therefore:

> **Every sandbox-completable row should become Finished in code and tests. External rows should remain External only when the missing input is genuinely outside the sandbox. No row should be called Finished merely because a schema, placeholder, or adapter exists.**
